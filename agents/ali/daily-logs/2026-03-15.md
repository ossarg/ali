## Módulo Agreements — detalles técnicos

### Migration 018
- Tabla `agreements`: id (UUID), case_event_id (FK→case_events), case_id (FK→cases nullable), agreement_type SMALLINT (1=mediacion, 2=juicio), claim_number, producer, beneficiary, concept, invoice_number, amount NUMERIC(14,2), due_date DATE.
- `extraction_status` SMALLINT: 1=pending, 2=completed, 3=failed.
- `extraction_raw` JSONB para output del pipeline.
- Índices: case_event_id, case_id, due_date (WHERE deleted_at IS NULL), deleted_at.

### Auto-creación
- Al aprobar un `case_event` de tipo `acuerdo` (mail_type=4), `case_service` llama `agreementService.CreatePending()` automáticamente.
- El acuerdo nace en `extraction_status=1` (pending); la extracción real la completará el pipeline de Ali.

- `services/agreement_service.go` — interface + implementación; método `CreatePending` para trigger desde case_service.
- `controllers/agreement_controller.go` — CRUD + GET /acuerdos/by-case/:case_id.
