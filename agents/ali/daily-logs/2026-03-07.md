## Evento principal: Integración SISE por Woz

### Resumen
Woz entregó la integración completa con SISE para siniestros. Es el cambio arquitectural más grande desde el inicio del proyecto:
- **Cliente SISE Go** con 3 queries registradas (GetClaimByNumber, GetPolicySummary, GetProducerByCode)
- **Redis** incorporado al stack (token cache con TTL − 60s buffer + retry-on-401)
- **2 migraciones** (007: tabla `claims` ~30 columnas; 008: FK `claim_id` en `cases`)
- **3 endpoints** bajo `/api/v1`: GET /claims, GET /claims/lookup?nro_stro=X, POST /claims
- **Tab "Siniestros"** en webapp con modal de búsqueda + lista

### Impacto en arquitectura de agentes
1. `claim_id` en `cases` habilita linkeo siniestro→caso (lógica de linkeo NO implementada aún — campo NULL)
2. Redis disponible en stack — usable para otros propósitos por agentes sin infra adicional
3. SISE como fuente de verdad — no hay endpoint agent-key aún; acceso actual solo via JWT de usuario
4. 3 query IDs hardcodeados — si pipeline necesita otras consultas SISE, hay que agregar nuevos IDs

### Nuevas env vars requeridas
```
REDIS_URL=redis://localhost:6379
SISE_BASE_URL=https://sise-consultas.libraseguros.com.ar/Sise3GBELibraCoreprodConsultas
SISE_USERNAME=<usuario>
SISE_PASSWORD=<password>
```
